# Documentation Workflow

## Overview

A structured documentation workflow helps maintain accuracy, consistency, and traceability throughout the product development lifecycle.

## Typical workflow

```text
Requirement
    ↓
Content planning
    ↓
Technical information gathering
    ↓
Drafting
    ↓
Technical review
    ↓
Editorial review
    ↓
Updates and approval
    ↓
Version control
    ↓
Publishing
    ↓
Maintenance
```

## Cross-functional collaboration

Technical writers typically work with:

- Product Management for requirements and feature intent.
- Engineering for technical implementation details.
- QA for behavior, validation, and known issues.
- Support teams for customer-facing troubleshooting scenarios.
- Documentation stakeholders for editorial consistency.

## Version control

Documentation changes should be traceable through version control.

A typical workflow can include:

1. Create a feature branch.
2. Make documentation changes.
3. Review the changes locally.
4. Commit with a meaningful message.
5. Open a pull request.
6. Address review comments.
7. Merge after approval.
8. Publish the approved content.

## Editorial ownership

Editorial ownership includes more than proofreading. It can include:

- Maintaining terminology consistency.
- Reviewing information architecture.
- Ensuring task procedures are complete.
- Identifying content gaps.
- Applying documentation standards.
- Coordinating reviews.
- Maintaining content quality across releases.
