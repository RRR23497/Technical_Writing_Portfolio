# Documentation Style Guide

## Voice and tone

Use clear, concise, task-oriented language.

Prefer:

> Select **Save** to create the profile.

Avoid:

> You should now go ahead and click on the Save button.

## Headings

Use headings that describe the reader's task or the information being presented.

Good:

```text
Configure a service profile
```

Avoid vague headings such as:

```text
Things to know
```

## Procedures

Use numbered steps for sequential tasks.

Use bullets for non-sequential information.

## UI elements

Use bold formatting for interface labels:

- **Save**
- **Settings**
- **Service Profiles**

## Terminology

Use one term consistently for the same concept.

For example, if the product uses **service profile**, do not alternate between:

- service profile
- service configuration
- service template

unless these represent distinct concepts.

## Error messages

Document the observable error, likely cause, and resolution.

## Editorial checklist

Before publishing, verify:

- [ ] Technical accuracy
- [ ] Terminology consistency
- [ ] Complete prerequisites
- [ ] Complete procedures
- [ ] Correct UI labels
- [ ] Working links
- [ ] Appropriate examples
- [ ] Consistent formatting
- [ ] Technical review completed
- [ ] Editorial review completed
